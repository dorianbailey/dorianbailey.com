## Stack

Plain HTML, CSS and JavaScript on GitHub Pages. No build step is needed to publish: commit to `main` and the site updates.

```
css/base.css          All styles. Palette, type and spacing are tokens in :root
js/main.js            Mobile menu, footer year
js/gallery.js         Photograph viewer (lightbox) on /photography/
assets/fonts/         Libre Caslon Text and Display, self-hosted (SIL Open Font License)
assets/img/           Portrait
assets/photos/        One folder per collection: full (2000px), t-*.jpg thumbnails (900px), s-*.jpg small (520px). photos.json lists them
tools/site.py         Generates every page (shared header/footer, contents, collections)
tools/photos.py       Builds web-sized photos + photos.json from the originals
tools/signature.json  The logo: Dorian's signature as SVG path data (see below); tools/signature-source.png is the drawing it was traced from
```

The pages are generated by `tools/site.py` so the header, footer and catalogue numbering stay consistent. To change copy, edit `site.py` and run `python3 tools/site.py .` from the repo root (small fixes straight in the HTML are fine too, but will be overwritten the next time the generator runs).

Photos are exported at 2000px (full), 900px (thumbnail) and 520px (small), converted to sRGB, with all camera metadata stripped. Every photo is served with `srcset`/`sizes`, so phones and small grid cells download the small file.

`assets/dorian-bailey-record.pdf` is the Record page printed with the print stylesheet (Letter, one page). After changing the Record, re-print it from a browser (Print, Save as PDF, Letter) or with Playwright's `page.pdf()`. `assets/img/og-card.jpg` is the 1200x630 share image used for link previews.

## Search

Each page has a name-first title and description, a canonical link, a per-page share image (`assets/img/og-*.jpg`) and JSON-LD structured data: Person and WebSite on every page, ProfessionalService for Dorian Bailey Photography, a Service for the estate sales, ProfilePage on the Record, and breadcrumbs. `sitemap.xml` is regenerated by `site.py` with every page and photograph; the 404 page is `noindex`. The services (photography types, inquiry email) live in `PHOTO_TYPES` and `MAILTO_PHOTO` near the top of `site.py`.

## The mark

The logo is Dorian's signature, traced from his drawing (`tools/signature-source.png`). `tools/signature.json` holds the path data in three sizes: `refined_display`, exactly as drawn (the home page, which writes it on stroke by stroke using the `centre` lines as a mask); `refined_text`, a hair heavier so the fine tips hold up small (header, footer, print; inlined once per page as `<symbol id="sig">`); and `refined_icon`, much heavier for tab icons (`favicon.svg`, `favicon.ico`, `favicon-32.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`). The share cards in `assets/img/og-*.jpg` carry the mark too, so regenerate them when it changes.

## Features

- **Bookings** (`js/book.js`, on every page): any `data-book="photo|estate|ads"` button opens a calendar; the chosen date fills in a short request, which is emailed through FormSubmit (`https://formsubmit.co/ajax/<form id>`): estate sale requests to bettersellingwithbailey@gmail.com, everything else to dorianbailey814@gmail.com. Both forms are activated; their private form IDs (`FORM_ID`, `FORM_ID_ESTATE` in `site.py`) are used instead of the addresses. If FormSubmit can't be reached, the visitor's own email app opens with the request written out instead. Services live in `SERVICES` in `site.py`; the photo types come from `PHOTO_TYPES`.
- **Journal** (`/journal/`, linked in the footer under GitHub): one file per post in `tools/journal/` (`<date>-<slug>.py`, each calling `post(dict(...))` with a `date`). A post goes live on its date: the six-hourly GitHub Action rebuilds the site in Eastern time and commits any new pages, so scheduled posts publish themselves. `JOURNAL_TODAY=2027-01-31 python3 tools/site.py .` previews the site as of another day (don't commit that build). Link between posts with `[[slug|text]]`, which stays plain text until the target is live. Each post gets BlogPosting structured data, a breadcrumb, a sitemap entry with its photographs and its own share card; `python3 tools/ogcards.py .` (after `site.py`, needs Playwright) renders cards for every post, scheduled ones included. Booking buttons can preselect a photography type with `data-book-type`.
- **What would I keep?** (`/better-selling/`, `js/calc.js`): payout = total sales - 20% - $995, the published standard terms.
- **Roll a detour** (`/oddway/`, `js/detour.js`): deals one random public stop live from OddWay's Supabase index, read-only with the project's publishable key. Category counts in the script are only used to pick a random offset.
- **The television** (`/metazoo/`, `js/tv.js`): plays the latest Bailey MetaZoo shorts from YouTube's privacy-enhanced player. `tools/youtube.py` refreshes `assets/data/youtube.json` from the channel's public feed; `.github/workflows/youtube.yml` runs it every six hours, rebuilds the pages and publishes.
- **Easter eggs** (`js/main.js`): a pair of red eyes blinks in the footer of every page now and then (soon after the footer scrolls into view). Click or tap them while they're showing and **Cryptid Highway** opens in a dialog. Typing "mothman" anywhere opens it too; typing "oddway" sends a VHS tracking sweep across the page.
- **Cryptid Highway** (`js/game.js`, markup in the footer's `<template id="cryptid-highway">`): a canvas driving game. Jump obstacles, photograph cryptids; personal best is kept in the visitor's browser; the game-over panel deals a real OddWay cryptid stop. The script is only downloaded the first time someone opens the game.
